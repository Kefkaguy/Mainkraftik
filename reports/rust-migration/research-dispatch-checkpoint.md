# Native research-job integration

The full Rust migration remains active and incomplete. This work is local. No deployed worker, trading policy, account, credential, model, forecast, archived evidence or website was changed. No external market-data or brokerage request was sent by these tests. Phase 7/8's negative trading-edge results remain authoritative.

Three existing research-job paths now use actual native services through the durable worker: refresh, information, and resolve. Refresh preserves registry checks, watchlist defaults plus SPY, input order and duplicates, the original resource projections, price/financial ingestion, information refresh, publication enrichment and both outcome resolvers. It preserves the original partial-result behavior when information fails. Information jobs propagate unexpected errors rather than quietly claiming success. Resolve jobs call both actual outcome resolvers.

The worker now supplies its durable job ID to dispatch. Existing fake-dispatch implementations retain their default behavior. Native refresh uses that ID for its ingestion run, so a failed final job transaction can recover the already committed ingestion result without fetching those prices again. Existing ingestion run IDs and histories are not rewritten. Typed array callers retain their previous interface; the native dispatcher also preserves Python's mapping-key/string iteration and the original persisted input shape for legitimate iterable inputs.

The new isolated PostgreSQL suite compares the unchanged Python enqueue/worker/dispatch pipeline against the Rust worker and native service composition. Network responses, clock, resource probes and generated identifiers are controlled; workflow functions are unchanged. Nineteen jobs cover normal refresh, information and resolution, default watchlists and empty symbol inputs, duplicate symbols, mapping inputs, unknown symbols, the 26-item research registry boundary, malformed/hashability errors, resource refusal, news denial, refresh partial results and uncaught information overflow. Job results, provider/IR requests, request order, delays, resource checks and eleven persisted data groups are compared. Seeded forecast and chart-detection outcomes require actual resolution; these are synthetic compatibility fixtures, not strategy returns or profitability evidence. Private article content is absent from source documents.

After the reference comparison, a database trigger deliberately fails the job's final transaction after real service side effects. A new worker recovers the running job, reuses its completed ingestion run, reaches attempt two, records one recovery event and performs no second SPY price fetch. A separate test cancels a caller while an actual provider request is paused: a competing worker cannot reclaim the live job, and draining the original owned task completes it after release. Test barriers/draining have finite deadlines.

An initial recovery probe selected SPY by a query parameter even though the original provider encodes that symbol in the URL path. The captured request trace identified the test-adapter mistake. Its unmodified log remains in `dispatch-recovery-probe-first-failure.txt`. The selector was corrected; the expected first-fetch count of one and the no-refetch recovery assertion were retained. The nineteen reference jobs and persisted-state comparisons had already passed before that probe failed.

Eight job types still require native dependencies and are explicitly unavailable: issue, evaluate, vision, research, audit, monitor, tune and nominate. They perform no provider work through this dispatcher and cannot silently use Python or substitute a strategy. This intermediate implementation is not a deployable worker configuration. Frozen prospective research dependencies, remaining model/research/training and evidence-publishing workflows, full raw error contracts, runtime roles, restore/rollback, Linux verification, full-service benchmarks and complete cutover remain open. The daily-to-hourly approximation and turnover/cost investigation remain separate work after functional parity.
