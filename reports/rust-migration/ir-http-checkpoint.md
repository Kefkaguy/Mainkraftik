# IR HTTP/session compatibility

Local migration work only. No deployed service, paper policy, account, credential, model or historical prediction was changed. These are transport compatibility tests, not trading-edge evidence.

The native IR transport now preserves cookies through redirects and requests within one ingestion or enrichment run, and creates a fresh cookie store for each subsequent run. The request and parser concurrency bounds remain shared across those sessions.

The first real TLS comparison passed basic session, domain/path, redirect, compression and decoded-size checks. Expanding the test to overlapping cookie paths exposed a mismatch: the default native cookie store sent the root cookie before the longer-path cookie. Python sent the longer-path cookie first. The unmodified negative result and request trace are retained in `ir-cookie-order-first-failure.json` and `ir-cookie-order-first-failure.txt`. Expected results were not reordered to hide the discrepancy.

The native store now uses deterministic nested-map insertion order and a stable longest-path-first sort. Expired entries are removed so later reissuance receives a new position. Original allowlisted hosts, certificate verification, redirect refusal, response limits and paper execution restrictions are unchanged.

`scripts/test-rust-ir-http.py` compares the unchanged Python `ir_get` against native reqwest using an actual HTTPS server bound only to loopback. Each run generates a temporary test CA and server certificate; both clients verify the certificate. DNS overrides prohibit external test requests. The native client uses the same session-factory path as ingestion/enrichment. The captured requests compare host, path, cookie header and user agent in exact order, in addition to response status, final URL, decoded content hash and text.

The expanded fixture covers 13 independent sessions, 46 explicit calls and 54 actual requests per client: redirect cookies, fresh-session isolation, deletion, replacement, multiple Set-Cookie headers, insertion order, duplicate names with overlapping paths, default paths, allowed shared-domain cookies, foreign-domain rejection, cross-host isolation, gzip, deflate, chunked UTF-8, 404 responses, exact/over-limit decoded bodies, external redirect refusal and redirect loops. All pass after the correction. A local Windows connection-abort while deliberately rejecting an oversized body is handled by the fixture server; application errors remain asserted.

The full checkpoint now explicitly runs this ignored native HTTP suite separately from the two native sentiment suites. The sentiment HTTP runner filters its own test so it cannot inadvertently execute the TLS suite without its required fixture. Checkpoints retain the public CA, Python oracle, native log and request-comparison report with output hashes. Private test TLS keys are never copied into checkpoint evidence. The fixture generator itself is included in source hashes.

This closes the covered real-wire cookie/compression checks. It does not establish universal equivalence for every malformed cookie, obsolete cookie protocol, charset, ISO timestamp or platform. Remaining migration gates include timestamp compatibility, original listing/article availability timing, long-backfill growth bounds, complete workflow dispatch, Linux verification, backup/restore/rollback, full-service measurements and verified cutover. No profitable trading advantage has been validated.
