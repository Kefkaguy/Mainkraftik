# Native immutable research storage

The complete Rust migration remains active and incomplete. These changes are local. No deployed service, paper policy, credential, account, enrollment, model, historical prediction or existing research artifact was modified. New writes in the tests use unique temporary stores. Native verification of existing archives is read-only. These results establish storage compatibility and recovery behavior, not a trading advantage.

The native store implements the existing chart, strategy-lab and compressed Phase 8 record formats. Canonical JSON bytes, record IDs, payload/read conventions, latest-pointer formats, published timestamps and reserved-field merge behavior are compared with unchanged Python. The bounded encoder preserves Python's compact and default-spaced JSON separators, Unicode escapes, signed zero and floating-point representation. Artifact byte budgets are explicit constructor arguments; the encoder and gzip decoder refuse oversized data rather than truncate it. The writer encodes borrowed payloads without cloning a large model, and payload reads move their value out of the wrapper rather than deep-copying it.

Final record files are installed exclusively from fully written, flushed temporary files. Duplicate writers verify the winning bytes and reuse the same identity; existing corrupt records are refused and remain unchanged. Pointer replacement uses a distinct temporary file and never deletes the previous pointer as a fallback. Publishers coordinate through an OS file lock, released on process death. Windows sharing/access errors during replacement receive a bounded retry of the retained staged file; exhaustion remains an explicit error. This fixes an independently reproduced concurrent-publication failure without weakening the complete-read assertions. The original failure log and its checksum remain retained.

The unchanged Python interruption probe writes half a record at its final filename and then raises. A retry detects an immutable-record conflict. The native process-exit tests terminate a separate process before and after record installation and pointer replacement. They require either the prior pointer or the complete new pointer, complete committed records, and successful retry. Abandoned temporary files are ignored; this code does not delete another worker's temporary files. Repeated publisher/readers, twelve simultaneous creators in each family, corruption refusal, decompression limits, and cancellation under a two-slot blocking-work budget are tested. Asynchronous write/publish helpers share that budget, and cancellation cannot release a slot while its blocking operation continues.

The controller journal uses the original SQLite evidence schema and append-only triggers, a two-connection pool and the original two-second busy timeout. Immediate transactions serialize semantic issuance. Duplicate keys retain their first payload; rollback leaves no evidence, lock capacity recovers, and a new process can resume after an uncommitted writer exits. Twelve competing issuers produce exactly one winning prediction. Python reads the native journal and verifies both duplicate prevention and the append-only trigger. No enrollment or strategy logic is executed by these storage primitives.

The reference corpus contains 139 finite JSON values and 24 chart/lab/compressed store cases. Python also cross-reads all 24 native-written artifacts. Gzip streams have matching header/trailer conventions and identical decoded canonical content and IDs; new compressed deflate streams need not be byte-identical across compressor implementations. Existing Python gzip files are reused without rewriting their bytes. The native CLI additionally verified all 27 existing compressed Phase 8 records; the largest decoded record is 172,302,359 bytes, within the verifier's explicit 256 MiB budget.

File contents are flushed on the current Windows host. Unix code additionally synchronizes created directory entries and committed parent directories. Linux execution and its durability behavior remain unverified. The process-exit tests are not power-loss tests. The native-source snapshot and negative evidence are preserved, but these primitives do not replace the still-required full database/model backup, restore and rollback procedure. Remaining workflow integrations, complete runtime configuration, full-service memory/CPU/latency measurements, strategy-horizon/cost work after parity, and verified cutover remain open. Nothing here authorizes deployment or model promotion.
