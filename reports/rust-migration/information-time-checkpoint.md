# Information timestamp compatibility

The full Rust migration remains active and incomplete. This work is local; no deployed service, policy, account, credential, model, forecast or archived research record was changed. Phase 7/8's negative trading-edge evidence remains authoritative.

The previous native information parser used RFC3339 plus two naive-date formats. The original Python `information.stamp` first replaces every uppercase Z with +00:00, calls CPython 3.14.2 `datetime.fromisoformat`, refuses timezone-naive results and converts aware results to UTC. Those behaviors are not equivalent.

The new private native adapter follows the reference parser's date/time separation, compact and ISO-week forms, arbitrary single separator, optional time components, fraction truncation, offset normalization, midnight rollover and validation order. Arithmetic stays in integer microseconds. UTC values outside Python's year range raise overflow rather than being clamped. Naive inputs remain refused; no local timezone is inferred.

Some reference conventions are surprising: a zero whole-second offset is treated as UTC even when its fractional component is nonzero; hour 24 can roll to the next date; error text uses the Z-replaced input and Python's string representation. These are preserved for migration parity, not adopted as a new data-quality policy. A generated, frozen Python Unicode 16.0 nonprinting table preserves representation of invalid strings. Source URLs, source/helper hashes, Unicode version and asset/fixture hashes are pinned under `third-party/python-time-provenance.json`; PSF notices are retained.

The unchanged Python implementation generated two new frozen synthetic fixtures: 1,788 main cases and 5,237 independent boundary cases. They include valid and invalid week/calendar forms, leap/year boundaries, normalized/out-of-range offsets, fractional offsets, midnight rollover, arbitrary separators, embedded NUL, invalid Unicode text, all nonprinting-range endpoints expressible as Rust strings, and deterministic string mutations. Native UTC microseconds, formatted comparison values, refusal classes and refusal messages match all 7,025 cases. Existing metadata/flag expectations were not edited.

The first raw negative result is retained in `information-time-first-failures.json`. Its 1,456 discrepancies included 43 test-adapter rendering differences where UTC microseconds were already identical: the adapter initially used the application's ordinary timestamp serializer against the fixture's explicit microsecond serializer. Correcting that adapter leaves 1,413 genuine baseline discrepancies. `information-time-baseline-analysis.json` retains the raw-result hash and separates those categories. The expected fixture was not changed. The raw evidence remains intact.

Parser tests alone do not prove caller behavior. Two additional isolated workflow failures reproduced handlers swallowing overflow as unavailable data even though Python propagates it. The raw news and IR failures are retained in `information-time-workflow-first-failure.txt` and `ir-time-workflow-first-failure.txt`; their hashes, the parser evidence hashes, and a separate original-Python no-database-write probe are retained in `information-time-negative-evidence.json`.

The native error boundary now preserves uncaught metadata exception classes. News handles only the original ValueError/ProviderError/KeyError families. Other metadata errors escape before a coverage record is written. Article parsing, archived filing acceptance timestamps, and publication enrichment retain overflow rather than converting it to a handled refusal. Ordinary invalid or naive publication metadata still follows the original skip behavior. The full differential now includes sixteen original news operations and twenty-four IR/refresh operations, adding compact/week timestamps, leap-second rejection, UTC overflow, a partial committed page followed by overflow, and publication-enrichment overflow. Complete persisted-table comparisons check that failed operations do not manufacture source, metadata or coverage records. A direct native unit test also requires both article and publication extraction to propagate overflow.

Checkpoint evidence now includes a ZIP of the exact tested native source and selected harness scripts, in addition to per-file hashes. The source snapshot is taken before commands run; a before/after identity gate refuses to report a passing checkpoint if those inputs change. ZIP bytes are themselves hashed in the output manifest. Private TLS keys and credentials are excluded. This is a native-source/harness snapshot; it does not replace the still-required full model/database/deployment backup and restore procedure. Older checkpoints remain untouched and do not retroactively acquire this new source archive.

Full exception/type coverage outside these timestamp paths, platform validation, stricter acquisition-time conventions, growth bounds, runtime integration, restore/rollback, benchmarks and verified cutover remain separate open migration requirements. The original listing timestamp is still sampled before article fetches; changing that convention requires a separately versioned correction. No trading policy or profitability conclusion follows from these transport/data compatibility tests.
