# Deployment gate and rollback

No deployment was performed as part of the local milestone. Never delete or inspect `/home/ubuntu/minecraft`, and do not alter its services, containers, volumes or backups. Do not prune Docker or remove legacy research data. All production commands must name only this new Compose project and its new volumes.

1. Build API/web images locally from the committed lockfiles. The optional vision image is excluded. Use `docker compose -f deploy/compose.yml build` with a new `deploy/.env` containing only this project's settings and independent database password. Do not copy the legacy production `.env`.
2. Record actual uncompressed image sizes, initial database/artifact sizes, compressed transfer sizes, temporary unpack/restore peak usage, and measured peak process memory. Docker was unavailable locally during initial implementation, so image sizes remain unverified; no estimate clears the gate.
3. Establish an off-host encrypted transfer/backup procedure for only the new database. `scripts/backup.py --output <new-file>.kfi.zip` makes a consistent binary-COPY archive and verifies it in a fresh receiving local database. It never overwrites a database. A receipt includes checksum, snapshot counts and restore result. `--off-host` is an operator attestation, not an independently detected fact. The initial local receipt deliberately records `off_host=false`.
4. Before creating production services, run `scripts/preflight.py --installed-bytes <measured> --temporary-bytes <measured> --backup-receipt <reviewed-receipt>` on the VPS. It checks projected free space after installation and working space against 10 GiB, and requires a reviewed off-host restore receipt. It never cleans data. If it fails, continue locally or provision storage separately.
5. Give the new web service an explicit `intelligence-web` alias on `intelligence-ingress`. Join only the existing nginx service to that new ingress network. API/PostgreSQL stay on the new private network; do not publish their ports. Keep the new worker limited to one concurrent job, 1 CPU and 768 MiB; the optional vision worker adds a separate 2 GiB budget if ever enabled. Do not build images on the VPS.
6. Back up the current nginx configuration to a new timestamped operator-controlled file outside protected resources. Add only `deploy/nginx-location.conf` to the existing HTTPS server block. Test with `nginx -t`, then reload nginx. Do not restart existing API, broker, campaign or Minecraft services.
7. Verify `/intelligence` login, direct unauthenticated API denial, CSRF denial, exact-origin enforcement, private port exposure, source links, data coverage, skipped-run reporting, and new-stack memory/disk headroom. Use fresh app credentials and key-based SSH; the disclosed SSH password must not be reused.

Rollback removes only the new nginx location/include and its newly added ingress attachment after `nginx -t`, then reloads nginx and stops only `keftrade-intelligence` services. Preserve all volumes and evidence. Never use `down -v`, global prune, or wildcard stop/delete commands.

The backup helper retains fresh `intelligence_restore_*` verification databases for inspection; it does not contain a cleanup command. Use a receiving cluster separate from production. Archive files include private source data and session hashes and must not be published or committed.
